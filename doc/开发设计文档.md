# 智能充电桩 APP — 开发设计文档

> 面向终端 `HarmonyOS`（ArkTS / Stage 模型）的单 Ability 应用。
> 需求来源：`doc/智能充电桩Story.xlsx`（16 条 Story，共约 12 人日）。
> 本文档作为开发蓝图，约定架构、页面路由、数据模型与实现顺序。

---

## 1. 项目概述

- 应用形态：手机端 App，充电桩充电服务。
- 核心流程：注册/登录 → 浏览附近充电站 → 选桩/扫码 → 启动充电 → 实时查看 → 结束充电 → 订单沉淀。
- 数据约定：**充电站、充电桩、实时充电数据均为本地模拟数据**，无需对接后端；账号体系用本地存储实现纯前端演示。

### 业务主线（依赖链）

```
注册(1)→登录(2)→[主框架导航(3)]
   ├─ 首页(4 充电状态卡片 / 5 附近充电站入口 / 16 我的)
   ├─ 充电(6 列表 →7 详情 →8 桩详情 →10 确认 →11 实时 →12 结束 →13 汇总)
   ├─ 扫一扫(9 →8 桩详情)
   └─ 订单(14 列表 →15 详情)
```

## 2. 技术栈与开发环境

| 项 | 值 |
|----|----|
| 运行系统 | HarmonyOS |
| 语言 | ArkTS |
| 模型 | Stage 模型，单 `UIAbility`（`EntryAbility`） |
| targetSdkVersion | `6.1.1(24)` |
| compatibleSdkVersion | `6.1.0(23)` |
| 组件框架 | ArkUI（声明式） |
| 状态管理 | `@State` / `@Prop` / `@Link` + `AppStorage` + `PersistentStorage` |
| 路由 | `Navigation` + `NavPathStack`（官方推荐，替代 `router`） |
| 持久化 | `@ohos.data.preferences`（账号、登录态、记住密码） |
| 测试 | `@ohos/hypium` |

> 决策说明：二级页面统一用 `Navigation` 的 `NavDestination` 管理（支持参数传递、返回栈、动画，优于 `router` 的页面切换）。启动页 `Login`、主框架 `Index` 仍以 `@Entry` 页面形式注册。

## 3. 整体架构与目录结构

### 3.1 分层

```
UI 层 (pages/component)     页面与可复用组件，只做展示与事件转发
    │
模型层 (model)              ArkTS 数据接口 / 类型定义
    │
数据层 (service/store)      本地模拟数据源、定时器模拟、业务逻辑，
```

## 5. 数据模型设计（`model/Types.ets`）

ArkTS 不支持 `interface` 作为运行时值，以下用 `interface` 定义类型、用常量数组承载 mock 数据。

```ts
// 用户账号
export interface UserAccount {
  id: string;
  username: string;
  password: string;   // 前端演示仅存本地，实际项目需加密
  avatar: string;     // 头像资源名
  createdAt: string;
}

// 充电桩状态
export type PileStatus = 'IDLE' | 'CHARGING' | 'OFFLINE';

// 充电桩
export interface ChargingPile {
  id: string;
  stationId: string;
  code: string;         // 桩编号，如 "P-001"，同时作为二维码内容
  powerKw: number;      // 功率 kW
  pricePerKwh: number;  // 单价 元/kWh
  interfaceType: string;// 接口类型，如 "GB/T 直流快充"
  status: PileStatus;
}

// 充电站
export interface ChargingStation {
  id: string;
  name: string;
  distanceKm: number;     // 距离 km
  freePiles: number;      // 空闲桩数
  pricePerKwh: number;    // 对外展示单价
  address: string;
  businessHours: string;  // 营业时间
  piles: ChargingPile[];
}

// 订单状态
export type OrderStatus = 'CHARGING' | 'FINISHED';

// 充电订单
export interface ChargingOrder {
  id: string;
  stationId: string;
  stationName: string;
  pileCode: string;
  startTime: string;
  endTime: string;
  energyKwh: number;    // 充电量 kWh
  unitPrice: number;    // 单价 元/kWh
  durationMin: number;  // 时长 分钟
  amount: number;       // 总价 元
  status: OrderStatus;
}

// 充电实时状态
export interface RealTimeChargingData {
  voltage: number;       // 电压 V
  current: number;       // 电流 A
  powerKw: number;       // 功率 kW
  durationSec: number;   // 已充时长 s
  energyKwh: number;     // 已充电量 kWh
  estimatedCost: number; // 预估费用 元
}
```

## 6. 本地模拟数据方案（`service` + `model/MockData.ets`）

| 数据 | 方案 |
|------|------|
| 充电站/桩 | 常量数组（≥3 个站、每站若干桩），`StationService` 提供查询方法 |
| 用户注册/登录 | `AuthService`：读写 `preferences`，校验账号唯一性、密码一致性 |
| 登录态/当前会话 | `AppStorage` 存 `currentUser` / `currentOrder` |
| 实时充电数据 | `ChargeSimulator`：`setInterval` 定时，按时间累加电量/费用，回调刷新 UI |
| 扫码 | demo 阶段用模拟扫码（从 mock 桩中选一个/输入桩编号）；可选集成 `@kit.ScanKit` 真实扫码 |

### 关键业务方法签名（示意）

```ts
// AuthService
register(username: string, password: string): boolean;   // 重复账号/空值校验
login(username: string, password: string): boolean;
saveRemember(username: string, password: string): void;

// StationService
getStations(): ChargingStation[];
getStationById(id: string): ChargingStation | undefined;
getPileById(pileId: string): ChargingPile | undefined;

// OrderService
startOrder(pile: ChargingPile): string;      // 生成订单 id，状态 CHARGING
finishOrder(orderId: string): ChargingOrder; // 结算，状态 FINISHED
getOrders(): ChargingOrder[];

// ChargeSimulator
start(pile: ChargingPile, intervalMs: number, onUpdate: (d: RealTimeChargingData) => void): void;
stop(): void;
```

- 主色沿用现状 `#1FA869`（`app.color.login_primary`）。新增页面级 color/float 资源统一放到 `resources/base/element/` 下，命名遵循现有 `login_*` 风格：`home_*`、`station_*`、`order_*`、`mine_*`。

## 10. 关键实现要点

- **登录成功进主框架**：`Login` 通过 `AppStorage` 记录 `isLoggedIn` + `currentUser`，用 `Navigation`/`router` 切换到 `Index`；或在 `EntryAbility` 启动时根据 `preferences` 判断直接进 `Index` 还是 `Login`。
- **跨页共享充电会话**：用 `AppStorage` 存全局单例 `currentOrder`，`HomeView` 的「充电中」卡片据此判断状态。
- **充电数据刷新**：`ChargeSimulator` 持有 `setInterval`，离开页面需 `clearInterval`，防止内存泄漏；建议在组件 `aboutToDisappear`/`onPageHide` 中停止。
- **扫码（Story 9）**：demo 阶段实现「模拟扫入桩编号」或从 mock 列表挑桩，识别成功后跳 `PileDetailPage`；如需真实能力，接入 `@kit.ScanKit`（申请相机相关权限见 `module.json5` 的 `requestPermissions`）。
- **返回栈**：二级页面使用 `NavPathStack.pushPathByName` / `pop`；避免 `@Entry` 页面间 `router` 混用导致栈混乱。

## 11. 隐私与安全（对接全局 CLAUDE.md 约定）

- 密码仅本地演示用途；**禁止**硬编码真实地址、密钥、凭证；敏感配置走 `.env` / 环境变量。
- 不提交绝对路径（`C:\Users\...`）。
- Commit 前做隐私扫描；提交信息用 Conventional Commits（`feat(scope): subject`）。
- 日志用 `hilog`，不 `print`。

## 12. 完成定义（Definition of Done）

- 页面可正常跳转，导航返回无误。
- 本地模拟数据加载正常，无空指针/越界。
- 充电状态刷新与结束逻辑正确，订单数据可持久查看（至少当次会话）。
- 各 `@Entry` 页面已注册进 `main_pages.json`。
- 主题/文案统一走资源文件，未硬编码。
